# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`tlschecker` is an experimental TLS/SSL certificate checker. It connects to remote hosts, inspects the X.509 certificates they present, and reports expiry, chain, revocation status, and a configuration grade. It ships as **both a library and a binary from one package** (`[[bin]]` + `lib.rs`).

## Commands

```sh
cargo build                      # debug build (openssl is vendored — needs a C toolchain + perl, no system openssl)
cargo build --release            # release build
cargo clippy --verbose           # lint (run in CI; keep clippy-clean)
cargo test                       # offline tests only
cargo test -- --ignored          # network integration tests (connect to google.com, *.badssl.com, digicert.com)
cargo test <name>                # run a single test, e.g. cargo test test_parse_host_port_with_port
cargo test <name> -- --ignored   # run a single network test
cargo run -- example.com         # run the CLI locally
```

MSRV is **1.88.0** (`rust-version` in `Cargo.toml`, required by ratatui 0.30); CI tests against both MSRV and stable. The binary requires the default-on `tui` cargo feature (`[[bin]] required-features`); library consumers can use `default-features = false` to skip the ratatui stack.

### Test convention (important)

Tests are split by network dependency:
- **Offline tests** run on every `cargo test`. Cert-parsing logic is tested with **synthetic X.509 certs generated in-process** (`make_test_x509`, `make_test_x509_signed_by`, `make_test_x509_weak_sig` in `lib.rs` tests) and with hand-built `TLS` structs (`make_test_tls`).
- `tests/exit_codes.rs` spawns the binary against loopback TLS servers with synthetic certs (an in-process `SslAcceptor` on `127.0.0.1:0`) and asserts exit codes; loopback is offline, not network, so it runs on every `cargo test`.
- **Network tests are marked `#[ignore]`** and only run with `-- --ignored`. They hit real external hosts and tolerate flaky responders (they accept `Good`/`Unknown` for revocation rather than asserting one).

When adding logic that touches a live TLS connection or OCSP/CRL responder, prefer an offline test using synthetic certs; gate anything that needs the network behind `#[ignore]`.

## Architecture

**`src/lib.rs` (`tlschecker` crate) — the core.** Everything funnels through `TLS::from_with_timeout(host, port, check_revocation, calculate_grade, timeout)`: it does TCP connect → TLS handshake → certificate/cipher extraction → optional revocation → chain analysis → hostname validation → optional grading, returning a `TLS` struct (`Cipher` + `CertificateInfo` + optional `TLSGrade` + optional `TlsScan`). `TLS::from(host, port, check_revocation, calculate_grade)` is the same call with `DEFAULT_TIMEOUT` (30s) and is kept as the stable four-argument entry point.

**Connecting (`resolve_addrs` + `connect_first_available`).** Resolution and connection are split out of `TLS::from_with_timeout` so `probe.rs` shares them. `resolve_addrs` returns *every* address DNS reports (resolving through the `(host, port)` tuple so IPv6 literals need no brackets); `connect_first_available` tries them in resolution order until one accepts — trying only the first, as the code originally did, fails a host that is up on another address, which is the normal outcome on an IPv4-only network whose resolver still returns AAAA first. The `timeout` is the budget for the **whole** connect phase, not per address: that bounds the worst case at what the caller asked for no matter how many addresses DNS returns (each check owns a worker thread), and costs nothing in the case that motivates the fallback, since an unroutable family or a refused connection fails instantly. When every address fails, the *last* connection error is returned so the reason describes a real attempt. All public types (`CertificateInfo`, `Subject`, `Issuer`, `Chain`, `RevocationStatus`, `SecurityWarning`, `TLSError`) and the free functions (`check_revocation_status`, `check_ocsp_status`, `check_crl_status`, `find_issuer_cert`, `analyze_certificate_chain`, `cert_matches_hostname`, `is_self_signed_certificate`) live here.

> **Design decision — do not "fix":** the handshake uses `set_verify(SslVerifyMode::empty())` (`TLS::from`). Peer verification is intentionally disabled because this is a diagnostic tool that must inspect expired, self-signed, and otherwise-invalid certificates. Trust decisions are made *after* inspection (self-signed detection, chain analysis, hostname matching, revocation), not by the TLS stack.

**Revocation flow:** `check_revocation_status` tries OCSP first (`check_ocsp_status`), falling back to CRL (`check_crl_status`) when OCSP is inconclusive. Both fetch URLs embedded in the certificate (AIA OCSP responders / CRL distribution points). OCSP **and** CRL responses have their signatures verified against the issuer before any status is trusted; verification failure degrades to `Unknown` (which triggers the CRL fallback) rather than a trusted result. CRLs are fetched through a process-wide `CrlCache` keyed by URL: concurrent checks naming the same distribution point wait on one download (a `OnceLock` per entry; the map lock is never held while downloading), successes are reused for `CRL_CACHE_TTL` (1h) and failures for `CRL_FAILURE_TTL` (60s, so a hung distribution point costs its 10s timeout once, not per host), and entries are evicted LRU beyond 16 CRLs / 16 MiB. Signature and freshness are still checked on every use. Downloads go through `read_body_limited` (CRL ≤ 32 MiB, OCSP ≤ 256 KiB). Tests exercise `CrlCache` with an injected fetch, so they never share the global instance.

**Certificate analysis & warnings:** `analyze_certificate_chain` produces `SecurityWarning`s for weak signature algorithms, incomplete chains, out-of-order chains (`is_chain_well_ordered`), and expiring/expired intermediates (within `CHAIN_EXPIRY_WARNING_DAYS` = 30; the leaf and self-signed roots are skipped). Hostname validation is separate: `cert_matches_hostname` checks SAN DNS entries (with single-label `*.` wildcard support, `matches_dns_name`) and falls back to the CN only when there are no DNS SANs; a mismatch is appended as `SecurityWarning::HostnameMismatch` in `TLS::from`. Each warning category that affects trust is mirrored into `GradingInput` (e.g. `has_hostname_mismatch` caps the grade at C, like self-signed). When adding a new `SecurityWarning` variant, classify it in `verdict::classify` (exhaustive, so it won't compile otherwise), add its `FindingCode` and label (`warning_label()` delegates to `FindingCode::label()`) and the README severity row, and wire `GradingInput` if it affects trust. `CertificateInfo` also carries `cert_sha256`/`cert_sha1` fingerprints (colon-hex, computed by `fingerprint()`) and a `#[serde(skip)]` `pem` field (full presented chain, leaf first) used by `--export-pem`. `cert_sn` is colon-hex (via `serial_hex`), not the decimal value of the ASN.1 INTEGER, so it matches CA portals, browsers, and `openssl x509 -text`.

**Issuer/revocation URLs.** `ocsp_urls` / `ca_issuer_urls` / `crl_urls` expose the endpoints embedded in the certificate. `ocsp_urls` comes from `openssl`'s `ocsp_responders()` — the *same* accessor `check_ocsp_status` queries, deliberately, so displayed responders can't drift from queried ones; `crl_urls` comes from the shared `crl_urls()` helper that `check_crl_status` also iterates (it collects every URI across all distribution points, so all are tried). `openssl` has no caIssuers getter, so `certext::ca_issuer_urls` walks the AIA extension (`1.3.6.1.5.5.7.1.1`) with the `der` primitives, filtering on the id-ad-caIssuers access method — same best-effort, never-panics contract as the rest of `certext`.

**`src/probe.rs` — protocol/cipher enumeration (`--scan`).** `scan_tls_with_timeout(host, port, timeout)` returns a `TlsScan` by attempting many single-version handshakes (`try_handshake` pins min==max proto version and one cipher / TLS 1.3 ciphersuite at a time) across SSLv3–TLS 1.3, enumerating accepted ciphers from curated candidate lists (`scan_tls` is the same with `PROBE_TIMEOUT`). The timeout is **capped at `PROBE_TIMEOUT` (10s)** — a caller can lower the per-handshake wait but never raise it, because ~100 handshakes at a 30s+ connect budget would take minutes. The target address is resolved **and connected once** up front (`resolve_addrs` + `connect_first_available`, then `peer_addr()`) and pinned for every handshake: re-resolving per attempt would hammer the resolver and risk probing different IPs of a multi-address host, making per-version results incoherent — and picking the address by actually connecting, rather than taking the first DNS answer, means a host whose first address is unreachable still gets scanned. It is opt-in and slow (many short connections). Note `scan_tls` only yields useful data for hosts reachable at ≥TLS 1.2, because `TLS::from` must complete a handshake first (modern OpenSSL's default floor is TLS 1.2) and the scan only runs in the `Ok` branch. Each `ProtocolSupport.version` is a typed `ProtoVersion` enum (not a string); `ProtoVersion::label()` is the single source for its display/JSON form, so `analyze_scan`/`scan_supports_obsolete_protocol` match on variants and a label change can't silently desync from the detection logic.

`--scan` implies `--grade` (`main.rs::should_grade` = `config_grade || scan`): a scan is only surfaced in the summary table through the grade, so grading is force-enabled whenever scanning. `TLS::from` then computes a negotiated-only grade and `apply_scan` upgrades it.

**Folding scan into results (`TLS::apply_scan`).** The `main.rs` worker calls `cert.apply_scan(scan)` after `TLS::from` (keeping `TLS::from`'s signature stable). `apply_scan` runs `analyze_scan()` — which emits `WeakProtocol` (SSLv3/TLS 1.0/1.1) and `WeakCipher` (`is_weak_cipher`: RC4/DES/NULL/EXPORT/anon/MD5) warnings for what the server *supports* — appends them to `security_warnings`, then recomputes the grade if one was present. Independently, `TLS::from` runs the private `analyze_negotiated(&cipher)` on every check (right after `analyze_certificate_chain`), emitting the same two variants for what was actually *negotiated* (SSLv2/SSLv3/TLSv1/TLSv1.1, or a weak negotiated cipher), so a host reachable only through the legacy-protocol retry carries a finding and is never Healthy while graded D (#217); with `--scan` both can appear, with distinct messages ("Connection negotiated …" vs "Server supports …"). `build_grading_input` does not read these two variants (it caps from the negotiated cipher and the scan directly), so the grade is unchanged. Grade inputs are built in one place, `build_grading_input(cipher, certificate, Option<&TlsScan>)`, used by both `TLS::from` (scan `None`) and `apply_scan` (scan `Some`); it derives the trust flags from `security_warnings`, `supports_obsolete_protocol` (SSLv3/TLS 1.0) from the scan, and `accepts_weak_cipher` from **both** the negotiated cipher name (`is_weak_cipher`, so a weak negotiated cipher caps the grade even without `--scan`) and the scan's accepted-cipher list. Both flags cap the composite grade at 69 (C max), alongside the existing self-signed / hostname-mismatch caps.

**`src/ct.rs` — Certificate Transparency lookup (`--ct-check`).** `check_ct_status(cert_sha256)` queries [crt.sh](https://crt.sh) by the leaf's SHA-256 fingerprint (an exact per-cert lookup that avoids the result-set caps a domain query hits on busy hosts). crt.sh has no JSON for fingerprint queries, so `parse_ct_html` matches the two stable HTML signals — a `?id=<n>` detail link (logged) or `Certificate not found` (absent). `CtStatus` is a **tri-state enum** mirroring `RevocationStatus`: `Logged { crtsh_id, crtsh_url }` / `NotLogged` / `Unknown`. `check_ct_status` returns the two *definitive* outcomes as `Ok` and "could not check" (network failure / unrecognized response) as `Err`; the worker maps that `Err` to `CtStatus::Unknown` and logs the reason via `warn!` (stderr) so a crt.sh outage is never collapsed into `NotLogged`. Like `--scan`, it is opt-in and network-bound, a **pure CLI flag off `Args`** (not part of `Config`), and folded in after `TLS::from` via `TLS::apply_ct(ct)` (mirroring `apply_scan`): only `NotLogged` appends `SecurityWarning::NotInCertificateTransparency` (`Unknown` adds no warning), then stores the status on `TLS.ct` (`Some` ⇔ `--ct-check` was requested). CT inclusion is **informational only** — deliberately *not* wired into `GradingInput`/grade caps, and classified `Info` in `verdict::classify` so it never changes a host's status, because legitimately private certs are often absent from public CT logs. Output: TextFormat prints a "Certificate Transparency:" block (yes/no/unknown); SummaryFormat shows a conditional `CT` column (`✓`/`✗`/`?`, hidden unless some host was checked — same pattern as the Grade column); JSON maps it to the `ct` object (`status` logged/not_logged/unknown + crt.sh id/url + `detail`); the not-logged finding is listed with the others via the verdict. Note: the tracing subscriber writes to **stderr** (see `src/diagnostics.rs`) so diagnostics never corrupt the stdout JSON/text stream.

**`src/sct.rs` — offline embedded-SCT parsing.** `embedded_scts(cert)` reads the leaf's Signed Certificate Timestamps from the X.509 extension OID `1.3.6.1.4.1.11129.2.4.2` (RFC 6962 §3.3) — offline proof the cert was *submitted* to CT logs, complementing the network `ct` *inclusion* check. The `openssl` crate has no generic extension accessor, so it is **dependency-free**: a small DER TLV walker (`read_tlv` → `find_extension_value`) structurally descends Certificate → tbsCertificate → the `[3]` extensions wrapper → each Extension (not a byte-pattern scan), then `parse_sct_list` decodes the TLS-serialized SCT list and `format_timestamp_ms`/`civil_from_days` render timestamps without a date crate. It is **best-effort and never errors** — absent/malformed structures yield an empty `Vec<Sct>`. Computed **always** (offline, cheap — no flag) in `get_certificate_info`, stored on `CertificateInfo.scts` (`#[serde(default, skip_serializing_if = "Vec::is_empty")]`). TextFormat prints an "Embedded SCTs" block when present and cross-references it in the `--ct-check` `Unknown` branch ("certificate was submitted to CT logs"); summary is unchanged (SCTs are always-on, so they don't drive the opt-in CT column).
**`src/grading.rs` — deterministic A+→F grading.** Pure functions over a transient `GradingInput`. Weighted composite: Protocol 30% · Cipher 25% · Key Exchange 15% · Cert Key Size 15% · Trust 15%, then **hard caps** (cap values are the tops of the `score_to_letter` bands, so they mean "this letter at best"): expired/revoked → 0 (F); negotiated TLS 1.0 or SSLv3 (protocol score ≤ 20) → cap 54 (D max); self-signed / hostname mismatch / weak cipher / scan-discovered obsolete protocol → cap 69 (C max). Grade is computed only when `--grade` is set and is serialized into `TLS` (skipped when `None`).

**`src/verdict.rs` — the single status.** `assess(&TLS, &VerdictPolicy) -> Assessment` (also `TLS::assess`) is a pure function returning a `Verdict` (`Healthy` < `Warning` < `Critical`, exhaustive on purpose; `label()` is the only source of its text) plus the `Finding`s behind it (`code: FindingCode`, `severity: Severity` Info/Warning/Critical, `allowed`, `message`). Every frontend reads it: the summary Status column, the text `Status:` line and "Findings" block, the JSON `status` object, the dashboard, the `tlschecker_verdict` gauge and the exit code — so they cannot disagree (#205). The severity table lives in `classify` (exhaustive over `SecurityWarning`, no `_` arm) plus the non-warning findings: expired / revoked / critical expiry window / hostname mismatch are **Critical** (every validating client rejects the cert, whatever its trust store); self-signed, untrusted, chain defects, weak algorithms, misissuance and the warning expiry window are **Warning** (private CAs are legitimate, so trust-store-dependent outcomes are never Critical); not-in-CT is **Info**. **Expiry windows** compare "fewer than" (`days < N`): fixed 15/30 days for lifetimes ≥ 90 days, the last sixth/third of the lifetime (in hours) for shorter-lived certs with no step at 90 days (`lifetime_hours` rounds so an LE 90d−1s span is exactly 2160h), fixed days when the lifetime is unknown (`valid_from_unix == 0`); an explicit `VerdictPolicy::min_validity_days` (`--min-validity`) **replaces** the critical window (0 disables it), the warning window always applies; all arithmetic is `i64`. `VerdictPolicy::allow` (`--allow`) marks a finding `allowed` — still reported, keeps its severity, excluded from the verdict, sorted last — except `expired`/`revoked`/`expires-soon` (`is_allowable`). **Never a finding:** revocation `Unknown`/`NotChecked`, CT `Unknown`/not requested, trust `Unknown`, and the grade (`tls.grade` is never read). The assessment is computed on demand and **never stored** on `TLS`, so it cannot go stale after `apply_scan`/`apply_revocation`/`apply_ct`. Semver policy: raising a severity or adding a Critical finding is breaking; lowering one or adding a Warning/Info finding is minor.

**`src/json.rs` — the versioned JSON output (`-o json`, #208).** JSON is the integration surface, so it is a **contract decoupled from the library's serde**: `render(reports, failures)` builds dedicated output structs (`Entry`, `Certificate`, `Connection`, …) instead of serializing `TLS`, so an internal rename can't reshape the output. Shape: `{"schema_version": SCHEMA_VERSION, "results": [...]}`, one entry per host **in input order, failures included** (`outcome` `checked`/`error`, `error {kind, message}`, `null` `status`/`connection`/`certificate` for errors; an invalid address has `null` `host`/`port`/`target`; `host` is the bare address — IPv6 without brackets — while `target` keeps `[v6]:port`). Rules: every key always present, `null` when it does not apply — the library's `"None"` placeholder for missing name attributes is mapped to `null` by `opt()`, and an uncomputable `*_unix` of `0` to `null`; timestamps are RFC 3339 (`tlschecker::rfc3339_from_unix`, the dependency-free formatter shared with `sct.rs`) with the Unix seconds alongside (also on each `chain` entry, which lists every presented certificate, leaf first); `version` is the X.509 number (`cert_ver` + 1); there is no `security_warnings` — every warning is a finding in `status`. It reaches the formatter through `Formatter::format_run(reports, failures)` (a default method that only `JsonFormat` overrides; text/summary leave failures to stderr). **Stability policy:** from schema 1 on, changes are additive only; renaming, removing or retyping a key bumps `SCHEMA_VERSION` (and the README *JSON output* section documents the shape).

**`src/diagnostics.rs` — stderr (#209).** `init(verbose, quiet)` installs the global subscriber **after** `Args::parse()` (so `-v`/`-q` pick the level): a `fmt` layer with the custom `CliFormat` event formatter — `error: …` / `warning: …` / `info: …`, no timestamp, no module path, no span fields (`-vv` adds `[target]`) — writing through `tracing_writer` (discarded while the TUI runs), filtered by a `filter::Targets` (no `env-filter` feature, so no regex dependency): WARN by default, ERROR with `-q`, INFO with `-v`, DEBUG with `-vv` — `-v`/`-vv` raise only the `tlschecker` target, third-party crates stay at WARN (ERROR with `-q`); a non-empty `RUST_LOG` parsed as `Targets` overrides it (an unparsable one is ignored with a warning). Colour only when stderr is a terminal and `NO_COLOR` is unset/empty (`use_color`). `failure_hint(detail)` maps the common raw errors (OpenSSL error stacks, OS errors) to a plain-language sentence by lowercase substring, most specific first (wrong version number → "does not speak TLS", refused, DNS, timeout, alert protocol version, handshake failure, unexpected EOF, certificate required, unrecognized name/SNI, address family, unreachable); it is the single source for the CLI failure line (`error: <label>: <hint>`, raw detail at `info`), the JSON `error.hint` and the dashboard's failed-host pane (`view::failure_lines`). Bare `tlschecker` (`std::env::args_os().len() <= 1`) with no `DEFAULT_CONFIG_FILE` (`tlschecker.toml`) in the CWD prints the help (exit 2) — decided in `run()` **before** `load_config`, not via clap's `arg_required_else_help` (a `tlschecker.toml` makes a bare invocation valid) and not in the config-error path (a broken `tlschecker.toml` must report its own error, not be hidden behind the help).

**`src/main.rs` — the CLI.** clap arg parsing, then either the interactive dashboard (see `src/tui/`) or output via the `Formatter` trait (`JsonFormat` / `TextFormat` / `SummaryFormat`) selected through `FormatterFactory`. **Output mode rule (`use_dashboard`):** the dashboard is the default when stdout is a TTY; piped/redirected stdout, an explicit `-o`, a config-file `output` key, or `--export-pem` keep the classic formatters — explicitness is captured in `load_config` *before* the defaults merge, because `Config::default()` seeds `output` with `Some("summary")`. Host checks run on a bounded worker pool (`spawn_checks`) that **streams** `(index, HostOutcome)` over an mpsc channel; the CLI path drains it fully into input-order slots, the TUI consumes incrementally. `check_host` returns `Result<TLS, TLSError>` — error presentation belongs to the frontend (CLI logs, dashboard renders a failed row). The pool size is `--concurrency` (`resolve_concurrency`: default `DEFAULT_CONCURRENCY` = 32, rejects 0 and > `MAX_CONCURRENCY` = 128), capped by the host count — **deliberately not** `available_parallelism()`: checks are network-bound (<1 ms CPU each), and on Linux `available_parallelism` follows the cgroup CPU quota, so a container limited to <2 CPUs got a single worker and checked hosts one at a time. The 128 cap is for open files (~2 sockets per worker; macOS defaults to 256). The connect budget reaches it through `CheckOptions.connect_timeout`, built by `resolve_connect_timeout`, which rejects both ends of the range rather than clamping: `0` would fail every check instantly and read as a network outage, and a value above `MAX_CONNECT_TIMEOUT_SECS` (3600) would overflow the `Instant + Duration` deadline in `connect_first_available` and **panic** the worker thread instead of failing validation. The flag is named `--connect-timeout`, not `--timeout`, because it deliberately bounds only connect + handshake reads — OCSP/CRL (10s each, per distribution point) and crt.sh (25s) keep their own timeouts, so it is not a per-host wall-clock cap. `warning_label()` is the single source for `SecurityWarning` display labels across all three frontends (it delegates to `FindingCode::label()`). Hosts are parsed by `parse_host_port` (accepts `host`, `host:port`, and `https://host:port`; strips IPv6 brackets; rejects invalid ports; a written port is always kept even when it is the scheme default — `Url::port()` drops it, so `written_default_port` recovers it, #221 — while a URL without a port, `http://` included, means 443). **Exit status (`src/exit.rs`):** fixed codes — 0 ok, 1 certificate problem (a checked host's verdict ≥ `--fail-on`, default `critical`), 2 usage/config (nothing checked: clap errors, config errors, no hosts, invalid `fail_on`/`output`, negative `min_validity`, legacy `exit_code` ∉ {0,1}, `--connect-timeout`/`--concurrency` out of range), 3 host(s) not checked (DNS/connection/handshake/certificate/caught worker panic, or an invalid address), 4 internal (`run()` returned `Err` after the run started, e.g. a dashboard terminal error). Precedence **2 > 4 > 1 > 3**: 1 beats 3 so a definitive cert failure is never hidden behind a flaky-network code. `--fail-on` (decides only exit 1) and `--allow-unreachable` (decides only exit 3) are independent; `--fail-on never` does not suppress 3; a run where hosts were attempted but none could be checked never exits 0 (`exit_status`'s `checked() > 0` guard), and invalid addresses (`KIND_INVALID`) are never exempt — they are a host-list typo. `main` returns `ExitCode` from `run() -> anyhow::Result<RunStatus>`; there is no `std::process::exit`. After the checks, `collect` turns the slots into `HostReport`s (`index` + `label` + `port` + `TLS` + `status: Assessment`, assessed once), `HostFailure`s (hosts that could not be checked, kept for JSON) and a `RunTally`. `TLS` carries only the hostname, so `port` (recovered from the label via `parse_host_port`, default 443) is what tells two ports of one host apart: `HostReport::target()` (`display_target`: `host` on 443, `host:port` otherwise, `[v6]:port` for IPv6) is the single name for a host in the summary row and findings header and the Prometheus `instance`; text prints a `Port:` line (#207). The `RunTally` holds per-verdict counts, `unreachable`, `invalid`, `pending` (never an error) and `trust_unknown`; `exit::explain` (logged with `error!`) names the findings and counts behind a non-zero code and the flag that changes it, `exit::notes` (`warn!`) reports tolerated unreachable hosts and an unverifiable trust store. `--scan`, `--export-pem`, `--ct-check`, `--allow`, `--allow-unreachable`, `--connect-timeout`, `--concurrency`, and `--generate-config` are **pure CLI flags read directly off `Args`** — they are deliberately *not* part of `Config`/`FinalConfig` (so config-merge code and its many test literals stay untouched). `fail_on` *is* a config key, deliberately, because it replaces the legacy `exit_code` key; `FinalConfig::from_merged_config` resolves them so **the new key beats the legacy one in any layer** and records deprecations for `main` to `warn!`. The deprecated `--exit-code`/`exit_code` (0 → `never`, 1 → default, anything else → exit 2) and the no-op `--fail-on-error` are hidden from `--help` and remain until v4. `--export-pem` bypasses the formatters and prints `certificate.pem` per host, but follows the same exit rules.

**`src/tui/` — interactive dashboard (binary-only, `tui` feature).** `mod.rs` owns the event loop: `ratatui::init()` (installs a terminal-restoring panic hook), drain the results channel with `try_recv`, redraw when dirty, poll crossterm input at 100ms; keys are dispatched per `Screen` — Fleet: j/k/arrows move, g/G, ⏎ opens the explorer, q/Esc quit; Detail (full-screen certificate explorer with every field: subject/issuer DNs, validity, serial, fingerprints, SANs, chain, SCTs, grade reasons, scan results): j/k scroll, PgUp/PgDn/Space page, g/G, Esc/⏎/Backspace back, q quits. **Export overlay:** `e` on either screen opens a modal filename prompt (`App::begin_export`), which the event loop intercepts *before* the per-`Screen` dispatch so typing can't trigger navigation keys; ⏎ commits (`commit_export`), Esc cancels (`cancel_export`), Ctrl+U clears and Ctrl+W drops a path segment. Overlay keys live in `handle_export_key` — extracted from `run` purely so they are testable without a terminal (`mod.rs`'s only tests). Its `Char(c)` arm is guarded by `!chord` (CONTROL|ALT, **not** SHIFT, which is how capitals arrive): unguarded, the catch-all typed a chord's letter into the filename, so Ctrl+D appended a literal `d`. `begin_export` only opens the prompt for a `Checked` slot — pending/failed hosts set an error `Flash` instead, so `e` is never a silent no-op. `commit_export` writes with `create_new(true)`: because the prompt is prefilled, overwriting is reported (`already exists`), never silent. **Only a successful write closes the overlay**; a failure keeps it open with the typed path intact and the reason in `ExportPrompt.error`, rendered *inside* the popup (which grows a line and turns its border red) rather than in the footer — the error must sit next to the input it describes. Editing via `export_input_push`/`export_input_pop` clears that error, because the event loop's prompt branch `continue`s before the footer flash-clearing runs, so a stale message would otherwise stay pinned while the user retypes the path. The prefilled name comes from `default_export_filename`, which runs the label through `parse_host_port` and sanitizes the result — labels are raw CLI input, so `https://host:port` and `host:port` would otherwise produce unwritable or Windows-illegal filenames. Results land in `App.flash` (`Flash { text, kind }` — the kind is explicit so rewording a message can't flip an error green), rendered by `draw_footer` in place of the key hints; the event loop clears it on the next keypress and tracks `had_flash` so the fallthrough arm's `dirty = false` can't cancel the redraw that erases it. `state.rs` holds `App` (labels + `Vec<Option<HostOutcome>>` slots + selection + `Screen` + `detail_scroll` + `export_prompt` + `flash` + `App.policy`); every on-screen verdict is `App::verdict_of` → `tlschecker::verdict::assess` (same as the CLI formatters, Prometheus and the exit code), recomputed per frame so on-demand `r`/`c` results show at once and count toward the exit status. The "Warnings" lists mark each line by severity (`✗`/`⚠`/`·`) and `(allowed)`. `view.rs` is pure rendering (`draw(frame, &App)`): fleet list + tally on the left, detail pane (facts, expiry `LineGauge` fed by the `valid_*_unix` fields, per-category grade gauges, warnings) on the right; fully testable via `ratatui::backend::TestBackend` (see its tests). While the TUI is active, the `TUI_ACTIVE` atomic makes `tracing_writer` discard diagnostics so they can't corrupt the alternate screen. The dashboard forces `calculate_grade = true` (offline, cheap). Hosts still pending when the user quits are returned as `None` and deliberately **not** counted as errors.

**Config precedence (spread across `main.rs::load_config` and `config.rs::merge_with`):** defaults (`Config::default`) → config file (`--config <path>`, or `tlschecker.toml` in CWD if present — optional, but once present a parse error is reported, never silently skipped) → CLI args (highest). Every field is `Option<T>` so merging is "last `Some` wins". `Config::example_toml()` is the canonical config schema (the README's inline TOML example mirrors it — keep them in sync).

**`src/metrics/prom.rs` — Prometheus push-gateway export** (`--prometheus`). Each host gets a **fresh registry** (`host_metric_families`) so values never leak between hosts; pushes per-host gauges (`tlschecker_days_before_expired`, `tlschecker_hours_before_expired`, `tlschecker_revocation_status` = 0/1/2/3, `tlschecker_grade_score` only when graded, `tlschecker_verdict` = 0/1/2 healthy/warning/critical from the report's `Assessment`, `tlschecker_below_min_validity` — explicit-only: driven by `--min-validity`, 0 when it is unset, independent of the default expiry windows) plus a `tlschecker_certificate_info` **info metric** (constant `1`) carrying the descriptive labels `cipher`/`cipher_protocol_version`/`issuer`/`grade`. **The push grouping key is stable identity only** — `job="tlschecker"` + `instance="<target>"` (`HostReport::target()`: `host`, or `host:port` off 443, so two ports of one host never share a key): a `push_metrics` PUT replaces series under the exact grouping key, so volatile labels (grade, cipher, expired) must stay *off* the key or every value change orphans the previous run's series in the gateway. That's why changeable metadata lives on the info metric (join on `instance`), not the grouping key. Diagnostics go through `tracing::warn!` (stderr), not `eprintln!`. Gated behind the `--prometheus` flag.

## Conventions

- Errors use `thiserror` (`TLSError` in `lib.rs`, `ConfigError` in `config.rs`); the binary uses `anyhow`. Map new failure modes onto an existing `TLSError` variant where possible.
- Public items carry rustdoc; doc examples compile as part of `cargo test` (doc-tests), so keep `# Example` blocks valid.
- Weak-algorithm detection (`is_weak_algorithm`) matches on substrings/OIDs of the signature algorithm string — extend the match list there rather than introducing a new mechanism.
